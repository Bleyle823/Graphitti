---
title: Supabase
description: Read live Supabase rows in workflows with URL + anon key only.
---

Add **Project Integrations → Supabase** with your project URL and anon key from [Supabase Project Settings → API](https://supabase.com/dashboard/project/_/settings/api).

| Action | Purpose |
|---|---|
| Get latest row | Newest row from any table (table + sort column) |
| Query table | Multiple rows with filters and limits |

## Credentials

| Variable | Required | Purpose |
|---|---|---|
| `SUPABASE_URL` | Yes | Project URL from Supabase dashboard |
| `SUPABASE_ANON_KEY` | Yes | Publishable anon key for read-only access |

Do not use the service role key in workflow steps unless you add write actions with strict RLS review.

## Get latest row

Reads the newest row from any table:

```
GET {SUPABASE_URL}/rest/v1/{table}?select=...&order={column}.desc&limit=1
```

| Field | Description |
|---|---|
| Table | Required. Any PostgREST table your RLS allows |
| Sort by column | Column used for newest-first ordering (e.g. `created_at`, `block_number`) |
| Sort direction | Newest first (default) or oldest first |
| Columns | `*` or comma-separated list |
| Schema profile | Optional non-public schema (e.g. `arbitrum`) |

### Outputs

| Field | Description |
|---|---|
| `latest` | Full row object |
| `rows` | Array (one row when limit is 1) |
| `has_match` | True when a row was returned |
| `alert_summary` | Present when the row includes `should_alert` |
| *column names* | Each column from `latest` is also exposed at the top level |

## Query table

Read multiple rows with PostgREST filters:

| Field | Description |
|---|---|
| Table | Required |
| Columns | `*` or comma-separated list |
| Sort by column | Optional |
| Row limit | Default 10, max 1000 |
| PostgREST filters | e.g. `status=eq.active` |
| Schema profile | Optional |

## Kelp rsETH example (Substreams → Supabase)

Use **Kelp rsETH Backing Monitor (Substreams → Supabase)** in the workflow examples sidebar:

1. Add Supabase credentials in Project Integrations.
2. Duplicate the example workflow.
3. Bind **Supabase** on **Get latest row** (preconfigured: `backing_snapshots`, sort `block_number`).
4. Replace the webhook URL placeholder.
5. Deploy with a KeeperHub block trigger on Ethereum mainnet.

```
Block trigger → supabase/get-latest-row → Condition (should_alert) → webhook
```

Substreams SQL sinks write `backing_snapshots` in Supabase (`substreams/README.md`).
